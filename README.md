# Hruder Simulator - Fingerprint Puzzle Solver

Automates the fingerprint hacking minigame in Hruder Simulator. Detects which 4 of the 8 fragment tiles match the target fingerprint using multi-scale template matching, navigates the selector to mark them in the optimal order, and handles chained puzzles automatically.

---

## Requirements

- Windows 10 / 11 (64-bit)
- Python 3.9 or newer → https://www.python.org/downloads/
- Hruder Simulator running on any monitor

Everything else (Python packages, Tesseract OCR) is installed automatically by `setup.py`.

---

## Installation

```
git clone https://github.com/YOUR_USERNAME/YOUR_REPO_NAME.git
cd YOUR_REPO_NAME
python setup.py
```

`setup.py` will:
1. Install all required Python packages
2. Download and install Tesseract OCR if not already present
3. Ask which monitor your game runs on (shows your actual detected monitors)
4. Ask you to press the key you want to use as the trigger
5. Write `config.json` with your settings

You only need to run setup once. Re-run it any time you change monitors or want a different trigger key.

---

## Usage

```
python fingerprint_solver.py
```

1. Open Hruder Simulator and navigate to a hacking terminal
2. **Press your trigger key** the moment the hacking screen opens — timing doesn't need to be precise, it will wait for the puzzle to load
3. The solver detects the fragments, marks the 4 correct ones, and submits
4. If multiple puzzles chain together, it handles them automatically — no second keypress needed
5. It stops and returns to idle the moment the hack ends
6. **F8** to quit the solver

### Console output

```

[CHECK] Puzzle #1 detected.
[SOLVE] Matching took 0.27s (rank4/rank5 margin: 0.082)
[SOLVE] Targets (optimal order, 5 moves): [(0,0), (0,1), (2,1), (3,0)]
[SOLVE] Marked (0,0)
...
[SOLVE] Submitted.
[CHECK] Processing/result overlay detected, waiting for it to clear...
[CHECK] Overlay cleared after 4.01s.

```

The `rank4/rank5 margin` value shows how confidently the correct fragments were identified. Values above ~0.05 are comfortable; lower values still work but indicate a harder-to-distinguish puzzle layout.

## Tuning

### Key delay (input speed)

The default `key_delay` of `0.02s` was measured on the developer's machine using `wasd_speed_test.py`. If you notice the selector skipping cells or marks not registering, increase it:

1. Edit `config.json` and raise `key_delay` (e.g. `0.03` or `0.04`)
2. Or run the speed tester to find your own floor:

```
python wasd_speed_test.py
```

Press **Numpad +** to start (delay steps down every 5s), press **Numpad -** when you see taps start missing. Check `speed_test_log.txt` for the exact delay at that point, then set `key_delay` to about 3× that value in `config.json`.

### Presence window

`presence_window` in `config.json` controls how long (in seconds) the solver waits for a puzzle to appear after you press the trigger. Default is `5.0`. Increase it if the puzzle sometimes loads slowly and the solver gives up before it appears.

### Recalibrating for a different setup

If the solver isn't detecting puzzles or exits too early on your machine, re-run `setup.py` to regenerate `config.json` for your monitor configuration.

## How it works

- **Detection**: samples the top-left fragment tile for texture (std deviation of grayscale). Above a threshold → fragments are present.
- **Matching**: multi-scale template matching (coarse pass across full scale range, fine pass around the best coarse peak) on all 8 fragments vs the large target fingerprint. Top 4 scores are the correct matches.
- **Navigation**: brute-forces all 24 visiting orders for 4 targets and picks the one requiring the fewest W/A/S/D taps from the starting position.
- **Chain detection**: monitors the PROCESSING/SIGNAL MATCH overlay box after each submit — only re-polls for a new puzzle once the whole check cycle has fully cleared. Monitors the CONNECTION TIMEOUT digits (coral-red color signature) to detect when the hacking session ends entirely.
- **Input lock**: a low-level Windows keyboard hook blocks your own W/A/S/D/Enter presses while the solver is marking tiles, so your keypresses don't interfere.
